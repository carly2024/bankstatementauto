# 総勘定元帳 × 銀行明細PDF 照合ルール

総勘定元帳（月次）の AA列（銀行PDFのURL）・AB列（銀行 該当ページ）を、銀行明細PDFと照合して埋める作業のルール集。
月が変わっても同じルールで実施する。ユーザーは「このルールで○月分をやって」と依頼する。

## 0. 前提

- 対象シート：`総勘定元帳_YYYYMMDD_YYYYMMDD`（月ごとのスプレッドシート）の「総勘定元帳」タブ。
- 8月分のスプレッドシートID：`1XrXnfhYLnO8Iud6w2gGnXxovLs6PE_g59_k-c4dpKTY`（7月分：`1SoE8T4uy1CmxEEmbuxJBC9J9psST-pw-uSAoYjrB728`）。
- 銀行PDFの置き場：「銀行フォルダ一覧」シート（`1MzNXuJ5Xjnp1M4oGGtY0NtArDgfdKJgSQnQQngTstF0`）にリンクのあるフォルダだけを使う。
  備考が「口座別フォルダではない」フォルダと、Maybank は除外。
- 店コル：`1toWzljK39eJOmpANM574Q3Obv-o0glOksGq_vmfgnIg` の「全共通_番号一覧＆振込名義」タブ。
  列A＝店舗管理番号（例 A005）、列C＝オーナー様名・振込人名（例 ヨシムラ　タケシ。`/` で複数名が書かれていることがある）。
- GAS は使わず、Drive・Sheets のコネクタで直接処理する。

## 1. 基本の照合（月次）

- 対象行：勘定科目が普通預金・外貨預金の行（りそな以外の銀行も含む）。AAが入力済みの行はスキップ（上書きしない）。
- 照合：取引日 ＝ PDFの勘定日（起算日）、貸方（Q）＝ 出金、借方（P）＝ 入金。
- PDF上の重複は（日付・残高・金額）で除く。
- 書き込み：
  - AA：PDFのURL。
  - AB：`pN rowM 番号`（番号はPDFにある場合だけ。127のように番号がない口座は `pN rowM`）。
  - 行数はヘッダーを数えず、各ページの先頭のデータ行を row1 とする。繰越行や金額のない行も数える。
  - ABの先頭に改行は付けない。
- 一致しない行は書き込まず、報告する。

### 色（AA列とAB列のみ）

| 状況 | 色 |
|---|---|
| 1件に決まる（テキストPDF、読み取りに問題のないスキャンPDF） | 白 |
| スキャンPDFで、読み取りに自信がない | 青 |
| 候補が複数ある | オレンジ（ABに全候補を改行で並べる。AAはリンクが同じなら1つ） |
| 一致なし | 書き込まない |

- 青は「内容が不確かなとき」に使う。スキャンPDFで読み取りに自信がないとき、および店コルの照合で名前は一致するが日付か金額が違うとき。
  スキャンPDFでも内容が確かなときは、白のままにする。
- 「順番どおりの1対1割り当て」は行わない（無駄な作業なので廃止済み）。
- 色は1行ずつ指定し、書き込み後に値と色を読み直して検証する（複数行を一括指定すると一部が反映されないことがあった）。
- 元帳にはフィルタがかかっていることがある。貼り付け（PASTE_VALUES）は非表示行を飛ばして値がずれるので、`values.update` などで明示的なセル範囲に書く。
- 最終報告：口座別に 単独 / あいまい(オレンジ) / 要確認(青) / 一致なし / スキップ / 未処理 の件数。一致なしは行番号・日付・金額も載せる。
- 合算で一致する場合（元帳の複数行の合計が、PDFの1件の振込と一致）は、その複数行すべてに同じAA・ABを書き、白にする。
- 借方・貸方がどちらも同額の振替行は、入金（借方）側の行を使う（7月分の小口1039行目、8月分の1149行目で採用）。

## 2. 摘要による候補の絞り込み（オレンジを減らす）

同日・同額で候補が複数ある行は、元帳の摘要とPDFの摘要（カナの名義、請求番号、支店名など）を見比べて推測する。

- 1件に決まる行：ABを該当1件だけにして、AA・ABを白にする。
- 決まらない行：オレンジのまま残す（無理に決めない）。
- 決め手の例：名義の一致（福田錦哲 → ﾌｸﾀﾞ ｷﾝﾃﾂ）、請求番号の一致（21274）、支店名（hangover梅田 → ｳﾒﾀﾞ）、
  一方が確定したときの消去法。
- 語呂合わせなどの弱い根拠は採用せず、ユーザーに確認する。

## 3. 店コルの名前で貼る（127【法人】三井住友銀行 生駒支店普通38 の行）

対象：列Dが「127【法人】三井住友銀行(ICカード認証)生駒支店普通38」の行のうち、上記のルールで貼れなかった行
（AA・ABが空の行、オレンジのまま残った行）。

1. 元帳の摘要から管理番号（例：【A005】）を読み取る。
2. 店コルの列Aが同じ番号の行を探し、同じ行の列C（振込人名）を取る。
3. 銀行PDFで「日付・金額・依頼人名」がすべて一致する行を探す。
   名前は全角・半角、スペース、カナの違いを吸収して比べる。列Cに複数名があれば、どれか1つでも一致すればよい。
4. 結果ごとの扱い：

| 状況 | AA・ABの扱い | 色 |
|---|---|---|
| 1件だけ一致 | AAにURL、ABに `pN rowM` | なし（白） |
| 複数件一致（同じ人が同日同額で複数回など） | AAにURL、ABに全候補を改行で並べる | オレンジ |
| 管理番号が店コルに見つからない | 既に入っている値を残す（消さない） | オレンジ |
| 名前に一致する行がPDFに1件もない | 既に入っている値を残す（消さない） | オレンジ |
| 名前は一致するが、日付か金額が違う | 貼らず、既に入っている値を残す。報告もする | 青 |

- オレンジだった行は、1件だけ一致した場合に白へ戻す。
- 既に入っている値は、最初の段階（基本の照合）で入れたもの。消さずに残す。

例：元帳800行目「【A005】 Balance Diner」→ 店コルの列C「ヨシムラ　タケシ」→ 8月の127のPDFで p4 row14（ヨシムラ タケシ、165,000円）。

## 4. PDFの読み取り（技術メモ）

- Driveの `read_file_content` が使えるPDFは、そのテキストから行を読む（127など）。
- テキストが空で返るPDF（りそなビジネスダイレクトの157など）は、`download_file_content` でPDFを取得し、
  `tools/extract_pdf_items.py` でページ内の文字列を取り出す。文字列は UTF-16BE で入っているので、
  通常のテキスト抽出（pdftotext など）では日本語が欠ける。
  `tools/pdf_rows.py` は、取り出した文字列を行（日付の行ごと）にまとめる。行の番号が ABの rowM に対応する。
- 暗号化PDFは pdfminer.six で開ける（パスワードは空）。

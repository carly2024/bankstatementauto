# 総勘定元帳 × 銀行明細PDF 照合ルール

総勘定元帳（月次）の AA列（銀行PDFのURL）・AB列（銀行 該当ページ）を、銀行明細PDFと照合して埋める作業のルール集。
月が変わっても同じルールで実施する。依頼時は「対象月のスプレッドシートURL」「対象口座」「新しいPDFのリンク」を伝えてもらう。
このファイルが正本。CLAUDE.md の「共通ルール」（空欄にだけ貼る、了承を得てから書く、候補は改行で並べる、ABの書き方、行の数え方、フィルタの注意、書いた後の確認）もあわせて守る。

## 進める順番（ユーザー確認済み）

1. まず、銀行明細PDFと元帳を照合して AA・AB を入れる（このファイルの1〜4章）。
2. 次に、1で AA・AB が入った行と「同じ取引」と見なせる行（同じシートの別の行や、別のスプレッドシートの行）があれば、その行の AA・AB をコピーする。
   同じ取引かどうかの見方は、CLAUDE.md の作業2（未払金：補助科目・金額・摘要）、作業3（EV：インボイス番号）、このファイルの5章（同じ取引No.）を使う。
   コピーするときも、空欄の行にだけ貼り、了承を得てから書く。

## 1. 基本の照合（月次）

- 対象行：勘定科目が普通預金・外貨預金の行（りそな以外の銀行も含む）。AAが入力済みの行はスキップ（上書きしない）。
- 照合：元帳の日付 ＝ PDFの勘定日（起算日）、貸方（Q）＝ 出金、借方（P）＝ 入金。
- PDF上の重複は（日付・残高・金額）で除く。
- 書き込み：
  - AA：PDFのURL（`…/view`）。ただの文字列で貼る。
  - AB：`pN rowM 番号`（番号はPDFにある場合だけ。127のように番号がない口座は `pN rowM`。りそな158は番号列があるので `p1 row1 001` のように付ける）。先頭に改行は付けない。
- 行の数え方（全銀行共通）：ヘッダーは数えず、各ページの先頭のデータ行を row1 とする。繰越行、金額のない行、「◯月末現在 残高」などの月末残高の行、空欄の行も、すべて1行として数える。
  - 例（奈良信金154）：2025/10/2 は p28 row25、2025/11/5 は p31 row3（月末残高の行を数えないと row23 / row1 になり誤り）。
  - 154の既存値（5776行の `p2 row32` など）には、月末残高の行を数えない旧い数え方のものがある。
- 候補が複数ある行は、ABに全候補を改行で並べる（AAはリンクが同じなら1つ）。色は付けない。
- スキャンPDFで読み取りに自信がない行も書き込み、報告の「要確認」に載せる。色は付けない。
- 一致しない行は書き込まず、報告する（「該当なし」とも書かない）。
- 「順番どおりの1対1割り当て」は行わない（無駄な作業なので廃止済み）。
- 合算で一致する場合（元帳の複数行の合計が、PDFの1件の振込と一致）は、その複数行すべてに同じAA・ABを書く。
- 借方・貸方がどちらも同額の振替行は、入金（借方）側の行を使う（7月分の小口1039行目、8月分の1149行目で採用）。
- 最終報告：口座別に 単独 / 複数候補 / 要確認 / 一致なし / スキップ / 未処理 の件数。一致なしは行番号・日付・金額も載せる。複数候補と要確認は行番号も載せる。
- 「できるところだけ対応して」と言われたら、特定できた行だけ書く。

## 2. 摘要による候補の絞り込み

同日・同額で候補が複数ある行は、元帳の摘要とPDFの摘要（カナの名義、請求番号、支店名など）を見比べて推測する。

- 1件に決まる行：ABを該当1件だけにする。
- 決まらない行：全候補を改行で並べたまま残す（無理に決めない）。
- 決め手の例：名義の一致（福田錦哲 → ﾌｸﾀﾞ ｷﾝﾃﾂ）、請求番号の一致（21274）、支店名（hangover梅田 → ｳﾒﾀﾞ）、
  一方が確定したときの消去法。
- 語呂合わせなどの弱い根拠は採用せず、ユーザーに確認する。

## 3. 店コルの名前で貼る（127【法人】三井住友銀行 生駒支店普通38 の行）

対象：列Dが「127【法人】三井住友銀行(ICカード認証)生駒支店普通38」の行のうち、上記のルールで貼れなかった行
（AA・ABが空の行、候補が複数のまま残った行）。

1. 元帳の摘要から管理番号（例：【A005】）を読み取る。
2. 店コルの列Aが同じ番号の行を探し、同じ行の列C（振込人名）を取る。
3. 銀行PDFで「日付・金額・依頼人名」がすべて一致する行を探す。
   名前は全角・半角、スペース、カナの違いを吸収して比べる。列Cに複数名があれば、どれか1つでも一致すればよい。
4. 結果ごとの扱い：

| 状況 | AA・ABの扱い | 報告 |
|---|---|---|
| 1件だけ一致 | AAにURL、ABに `pN rowM`（候補が並んでいた場合はその1件だけにする） | 単独 |
| 複数件一致（同じ人が同日同額で複数回など） | AAにURL、ABに全候補を改行で並べる | 複数候補 |
| 管理番号が店コルに見つからない | 既に入っている値を残す（消さない） | 要確認 |
| 名前に一致する行がPDFに1件もない | 既に入っている値を残す（消さない） | 要確認 |
| 名前は一致するが、日付か金額が違う | 貼らず、既に入っている値を残す | 要確認 |

- 既に入っている値は、最初の段階（基本の照合）で入れたもの。消さずに残す。

例：元帳800行目「【A005】 Balance Diner」→ 店コルの列C「ヨシムラ　タケシ」→ 8月の127のPDFで p4 row14（ヨシムラ タケシ、165,000円）。

## 5. Apps Script（fillBankColumns.gs、AA・AB補完）

- 同じ取引No.（A列）の行から、空欄のAA・ABを補完する。値が複数ある場合は、重複を除いて改行で連結する。
- 既存の値と数式は上書きしない。取引No.が空の行は処理しない。
- 対象は、表示中で名前に「総勘定元帳」を含むシート。1行目はヘッダー。
- スクリプトは banktransactionNo.auto リポジトリにある（コミット a40f296）。

## 6. AA列に貼れない行の理由（調査結果）

- AAに貼れるのは、通帳の動きと同じ仕訳に入っている行だけ。
- 売掛金の計上行（借方）は、入金行と別の取引No.の別仕訳。同じ取引No.では補完できない。摘要の請求No.（5桁）で入金行と突き合わせる方法がある（174件一致）。
- 仮払金の取崩し行（貸方）は貼れない。取崩し行に「元の入金No.」の列を持たせる運用が確実。仮払消費税、EV工事原価、未成工事支出金（EV）は、仮払金の取崩しに連動して空欄になる。
- 相手が未払金・諸口の仕訳は、その仕訳内に銀行の動きがなく、AAを埋めようがない。

## 7. PDFの読み取り（技術メモ）

- Driveの `read_file_content` が使えるPDFは、そのテキストから行を読む（127など）。
- テキストが空で返るPDF（りそなビジネスダイレクトの157など）は、`download_file_content` でPDFを取得し、
  `tools/extract_pdf_items.py` でページ内の文字列を取り出す。文字列は UTF-16BE で入っているので、
  通常のテキスト抽出（pdftotext など）では日本語が欠ける。
  `tools/pdf_rows.py` は、取り出した文字列を行（日付の行ごと）にまとめる。行の番号が ABの rowM に対応する。
  行の数え方（1章）に合わせて、月末残高の行や空欄の行も1行として数えているか確認する。
- 暗号化PDFは pdfminer.six で開ける（パスワードは空）。

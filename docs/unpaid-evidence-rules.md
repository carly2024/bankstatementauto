# 未払金の証憑リンク転記ルール

総勘定元帳で、勘定科目（C）が「未払金」の行のうち AA・AB（証憑リンク・ページ情報）が空の行に、
対になる行（同額・貸借逆・摘要が似ている行）の AA・AB を転記する作業のルール集。
元は `test-repo` の `未払金_証憑転記プロンプト_最新版.md`。月が変わっても同じルールで実施する。

## 0. 対象シート

- ① 書き込み先：当月の元帳（例：`総勘定元帳_20260701_20260731` の「★総勘定元帳」タブ）。
- ② 元行を探すための参照のみ：翌月以降の元帳（例：`総勘定元帳_20260801_20260831`）。書き込み・バックアップ不要。
- ①②は同じ列構成。C=勘定科目、D=補助科目、O=摘要、P・Q=借方・貸方、AA=銀行（リンク）、AB=銀行該当ページ。
- ①より前の月の計上行は対象外（スキップ）。
- 補助科目で対象を絞るよう指示されたとき（例：「D が従業員」）は、Dの完全一致で空行を絞る。元行は絞らず全行を使う。

## 1. 用語

- 元行：C=未払金、P・Qに金額があり、AAがリンク（httpで始まる）で、ABも入っている行。
- 空行：C=未払金で、AA・ABが空の行。書き込み先は①の空行のみ。
- AAがリンクでない行（ファイル名だけ、「N/A」など）は元行にしない。件数と行を報告する。
- すでに AA・AB が入っている行（前回の書き込み分、手で直した行を含む）はスキップする。

## 2. 基本のペア探し（1対1）

- 金額が同額で貸借が逆の行を対象にする。
- 摘要の類似度で並べる。類似度は、正規化した摘要の2文字組の一致率（Dice係数）。
  正規化：全角・半角を統一、先頭の「出金」「振込」、空白・記号・「㈱」「株式会社」を除く。
- ①②の全シートをまたいで探す。取引先では分けず、全行に同じルールを当てはめる。

### 区分

1. 候補なし → 何もしない。
2. 候補が1件 → 類似度が0.5以上ならA。0.5未満ならC（オレンジ）。
3. 候補が複数 → 1位の類似度が0.8以上で、2位との差が0.2以上ならA。
4. それ以外は、支払日（取引日の月）で絞る。支払いは原則、計上日の翌月末。
   - 翌月払いの候補が1件 → A。
   - 翌月払いがなく、翌々月払いが1件 → A。
   - 翌月払いが2件以上のときは、翌月の月末営業日に支払われた候補が1件ならA。
     翌月払いがなく翌々月が2件以上のときも、同じ基準で翌々月の月末営業日の1件に絞る。
   - 上の絞り込みでも2件以上残る（同じ日に複数ある）→ C。
   - 翌月・翌々月に該当なし → C。
   - 当月、前月以前、3か月以上先の候補は、この段階の判断から外す。
   - 空行が支払い（借方）側のときは、月の向きを逆にして、1か月前、2か月前の計上行を探す。
5. 絞り込みで決まった行（A）でも、次の場合はCにする。
   - 摘要の類似度が0.2未満。
   - 同じ元行を、ほかの空行も採用している（元行は1行ずつしかないため）。

### 月末営業日

- 月末が土日祝のときは、その前の営業日を月末とみなす（例：2025年11月は11/28が月末）。
- 12月だけは12/30を月末とする。12/30が土日祝のときは、その前の営業日（日曜なら12/28）。
- 祝日、年末年始の休みも休みとして扱う。
- 摘要の「○月分」「○月末振込分」が、計上側と支払い側で合っているかも見る。

## 3. 合算ルール（複数行の合計が元行1件と合う）

1対1で「候補なし」になった空行は、複数の空行の合計が元行1件の金額と合うかを調べる。
（例：取引No 1380（37,620円）+ 1381（59,400円）= 1382（97,020円）、
取引No 2463 の3行（198,000 + 44,660 + 5,720円）= ②の取引No 2467（248,380円））

- 対象：1対1で候補なしだった空行どうし。貸借が同じ側で、補助科目が同じ行。
- 合算する行は、同じ日付、または近い日付で、取引Noが連続するもの、同じ取引Noのものに絞る。
  組み合わせを総当たりしない（偶然の一致を避けるため）。
- 合計が、貸借逆の元行1件の金額と一致し、摘要の内容も合うとき：
  - 合算した行すべてに、同じ元行の AA・AB を貼る。色は付けない（白）。
  - 元行が②にあっても、書き込み先は①の空行のみ。
- 摘要が合わない、または合計が一致する元行が複数あって決まらないとき：Cにする（候補を全部並べてオレンジ）。
- 元行は、1件の合算グループにしか使わない。ほかのグループも同じ元行を使うときはCにする。
- 合算で決めた行は、最初に一覧を出して、確認を受けてから書き込む。

## 4. 貼り付け方

- A：その1件の AA・AB を貼る。ハイライトなし。ABの先頭の改行と末尾の空白は除く。
- C：全候補を改行で並べて貼り、AA・ABだけにオレンジ（#FF9900）を付ける。
  - 類似度の高い順に、全件入れる（件数の上限は付けない）。
  - AAは「取引No: リンク」の形。
  - ABは取引Noを入れず、ページ情報だけをAAと同じ順番で改行する。AAとABの行数を揃える。
    元行のABが複数行のときは、1行にまとめる（空白でつなぐ）。
  - 取引Noと証憑が同じ候補が重なることがある。そのまま全部入れる（確認するとき、重複は1つにまとめて読む）。
- 候補なし：何もしない。
- Cは、確認する人が正しい1件を残して他を消し、ハイライトを外す。
- 合算：3. のとおり。

## 5. 進め方（各段階で止まって確認する）

1. 各シートのメタ情報（タブ名、行数）を確認する。
2. ①②の未払金の行を全部読み込み、元行と空行に分ける。件数を報告する。
   - 大きいシートは、5,000行ずつに分けて読む（一度に読むと接続が切れる）。
   - AAが空の月（元行になれない月）があれば報告する。
3. 区分の件数（A／C／候補なし）と注意点を報告する。一覧はファイルにまとめる
   （空行ごとに候補を並べ、区分、理由、所在・取引No・日付・月差・類似度・AA・ABを出す）。
4. 問題点を洗い出して報告する。
   - 同じ元行を取り合う空行
   - 類似度が低いのに絞り込みで決まった行
   - 元行にならない AA（リンクでない値）
   - フィルター、保護範囲、結合セル（書き込みを妨げるもの）
5. 確認する人が区分を直す。ここで止まり、「進めて」と言われるまで書き込まない。
6. 「進めて」の後：
   1. ①のメインタブを複製して、バックアップタブを作る（名前：`【タブ名】_バックアップ_日付`）。
   2. 書き込み前の状態を控えとして保存する。
   3. ①が変わっていないことを確認する（リビジョンを指定する）。
   4. A・Cの値とオレンジを書き込む。
7. 読み戻して、①を最後まで書き込み前の控えと比較する。
   - 変更されたセルが、書き込み対象の行の AA・AB だけであること。
   - 書き込んだ全行の、取引No、AA、ABが期待値と一致すること。
   - Cのオレンジが付いていること。
8. 想定外の変更があれば、すぐ止めて控えで戻し、状況を報告する。

## 6. 書き込み方法の注意

- `pasteData` は使わない。`updateCells` で、行・列を明示して書く（フィルターで隠れた行の影響で、1行ずれて既存データを上書きした失敗があったため）。
- 行は取引Noで照合し、書き込み直前に、行番号がずれていないこと、AA・ABが空であることを確認する。
- 書き込むのは、空行の AA・AB と、そのハイライトだけ。それ以外のセルは変更しない。
- Aの行には、ハイライトの書式を書かない（もとからある色はそのままにする）。
- ②のシートと、バックアップタブには書き込まない。
- 最後に、結果（A・C・候補なしの件数、変更したセル数、バックアップタブの名前、残る手動確認の件数）を報告する。
